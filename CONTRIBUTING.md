# Contributing

Thanks for helping. This is a browser editor for .docx files written in plain JavaScript (ES modules, no framework,
no TypeScript build step), on top of ProseMirror.

## Setup

```sh
npm install
npm test            # unit tests in Node: reading, round trips, edits, tracked changes, styles, charts, equations
npm run lint        # ESLint: mistakes (unused or undefined names), not formatting
npm run dev         # demo at http://localhost:8080 (drag a .docx onto it)
npm run test:e2e    # Chromium: open, edit and save each fixture; accessibility, forms, charts, text boxes, co-editing
node tools/check-ooxml.mjs test/out   # structural check of the files test:e2e saved
```

The browser tests need Node 20 or later (Playwright) and a Chromium: `npx playwright install chromium`.
CI (`.github/workflows/ci.yml`) runs all of the above on every push and pull request.

## Where things are

- `docs/ARCHITECTURE.md`: how it works, a map of every module, and how a keystroke becomes pages, a print and a saved
  file. Start there.
- `docs/LAYOUT.md`: how layout is matched to Word, the rules found and what was tried and dropped. Read it before
  changing how lines or pages are placed.
- `docs/ACCESSIBILITY.md`: WCAG 2.1 AA conformance notes, with the test that backs each claim.
- `tools/word-compare/`: the comparison with Word's own PDFs (see below).

## How the code is written

- **Keep what isn't understood.** Anything in a .docx the editor doesn't model is kept as raw XML and written back as
  it came in; only what the user changed is rewritten. Never drop or regenerate a part you don't need to.
- **Layout is decoration.** Page breaks, spacers, list labels and print shifts are ProseMirror decorations or CSS,
  never document content, so they never reach the saved file or the undo history.
- **Comments say why.** What Word does and the measurement that showed it, not what the next line does. Refer to a
  private test document by its label (`sample S078`), never by its name.
- **One concern per change**, with a test where one fits: `test/*.test.js` for reading and saving, the browser suites
  (`test/*.mjs`) for what needs a page.
- Match the surrounding code: naming, comment density, two-space indents (`.editorconfig`). Keep new lines to about
  120 characters (most are; some older ones run longer).

## Changing layout

1. Get Word's PDFs of the documents you measure with, once (`tools/word-compare/word-print.ps1`).
2. Run the comparison before your change and after it (`tools/word-compare/run.ps1`, then `diff.py` on the two
   reports). See `tools/word-compare/README.md`.
3. Keep the change only if the total doesn't get worse and every document that got worse is understood. Never compare
   with another word processor's output, only Word's.
4. Add the rule it establishes to `docs/LAYOUT.md`, and say in the code comment what it fixed.

## Saved files

Saved files must open in Word without repair: run `tools/check-ooxml.mjs` on what you saved, and for anything new in
the format, open the saved file in Word itself.

## Test documents

Fixtures in `test/fixtures` are generated by the scripts in that folder, so the repository holds no third-party
documents. Please don't add real-world documents, Microsoft fonts or templates to the repository; describe what a
document needs and generate one instead (`test/fixtures/make-layout-corpus2.mjs`, `mkchart.mjs` show how).
